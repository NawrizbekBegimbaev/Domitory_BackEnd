================================================================================
                    DORMITORY - ИНСТРУКЦИЯ ПО СИСТЕМЕ
================================================================================

Платформа управления университетским общежитием.
Заменяет бумажный учёт и автоматизирует работу администрации.

================================================================================
1. ДОСТУП К СИСТЕМЕ
================================================================================

Веб-приложение:  https://begimbaev-dormitory.uk
API:             https://begimbaev-dormitory.uk/api/v1/
API-документация: https://begimbaev-dormitory.uk/api/docs/

Мобильное приложение (Flutter): устанавливается на устройство вручную.

--------------------------------------------------------------------------------
1.1. Вход в систему
--------------------------------------------------------------------------------

Два способа входа:
  1) Email + пароль
  2) Телефон + OTP-код через Telegram

Для входа через Telegram:
  - Откройте бота в Telegram
  - Нажмите /start и отправьте свой контакт (номер телефона)
  - После привязки — вводите номер телефона на странице входа
  - OTP-код придёт в Telegram

--------------------------------------------------------------------------------
1.2. Роли пользователей
--------------------------------------------------------------------------------

  platform_admin   — Полный доступ ко всему
  university_admin — Администратор (всё кроме системных настроек)
  dorm_manager     — Комендант (жильцы, комнаты, договоры)
  accountant       — Бухгалтер (финансы, платежи, отчёты)
  security_staff   — Охрана (только просмотр, контроль доступа)

================================================================================
2. УПРАВЛЕНИЕ ИНФРАСТРУКТУРОЙ
================================================================================

--------------------------------------------------------------------------------
2.1. Корпуса
--------------------------------------------------------------------------------

Корпус — здание общежития.

Поля:
  - Название (обязательно)
  - Адрес
  - Гендерная политика: Мужской / Женский / Смешанный
  - Статус: Активный / Неактивный

Действия: создание, редактирование, удаление.
Удаление невозможно если есть этажи с комнатами.

--------------------------------------------------------------------------------
2.2. Этажи
--------------------------------------------------------------------------------

Этаж привязан к корпусу. Номер этажа уникален в пределах корпуса.

Действия: создание, редактирование, удаление.

--------------------------------------------------------------------------------
2.3. Комнаты
--------------------------------------------------------------------------------

Комната привязана к этажу.

Поля:
  - Номер комнаты (уникален в пределах этажа)
  - Вместимость (количество кроватей)
  - Ежемесячная цена (за одно место)
  - Гендерная политика
  - Статус: Свободна / Занята / Ремонт / Закрыта

Статус обновляется автоматически:
  - При заселении: если все места заняты → "Занята"
  - При выселении: если появились места → "Свободна"

================================================================================
3. РАБОТА С ЖИЛЬЦАМИ
================================================================================

--------------------------------------------------------------------------------
3.1. Создание жильца
--------------------------------------------------------------------------------

Обязательные поля:
  - ФИО
  - Пол
  - Номер телефона

Дополнительные поля:
  - Дата рождения
  - Email
  - Студенческий ID
  - Факультет
  - Курс
  - Фотография
  - Заметки

Статусы жильца:
  - Ожидающий — только создан, ещё не заселён
  - Активный  — проживает в комнате
  - Выселен   — договор расторгнут
  - Выпустился — окончил обучение
  - Приостановлен — временно не проживает

--------------------------------------------------------------------------------
3.2. Опекуны
--------------------------------------------------------------------------------

Для каждого жильца можно добавить опекунов:
  - ФИО опекуна
  - Степень родства (отец, мать, брат/сестра, дядя, тётя, другое)
  - Номер телефона
  - Экстренный контакт (да/нет)

--------------------------------------------------------------------------------
3.3. Документы
--------------------------------------------------------------------------------

Типы документов: ID-карта, Паспорт, Водительское удостоверение.
Загружается файл + номер документа.

================================================================================
4. ЗАСЕЛЕНИЕ
================================================================================

Полный процесс заселения:

  1. Создать жильца (раздел "Жильцы" → "Добавить")
  2. Добавить опекуна и документы
  3. Создать договор:
     - Выбрать жильца
     - Выбрать корпус
     - Указать даты начала и окончания
     - Номер договора генерируется автоматически
  4. Назначить комнату:
     - Выбрать комнату из свободных
     - Система проверит гендерную политику
     - Система проверит наличие мест
  5. Автоматически:
     - Статус жильца → "Активный"
     - Создаются начисления на весь период договора
     - Записывается история проживания
     - Создаётся запись в аудите

--------------------------------------------------------------------------------
4.1. Покупка всей комнаты (групповое заселение)
--------------------------------------------------------------------------------

Несколько жильцов могут купить всю комнату целиком:
  - Стоимость = цена комнаты x вместимость
  - Делится поровну между всеми жильцами
  - Каждому назначается пропорциональное количество мест

Пример: комната на 4 места, цена 500 000 за место.
  3 жильца покупают всю комнату:
  Общая стоимость = 500 000 x 4 = 2 000 000
  Каждый платит = 2 000 000 / 3 = 666 667

Если один из группы выселяется:
  - Остальные пересчитываются на 1 место каждый
  - Начисления пересчитываются по обычной цене

================================================================================
5. ВЫСЕЛЕНИЕ
================================================================================

При расторжении договора:

  1. Текущий месяц — пересчитывается пропорционально дням проживания
  2. Будущие месяцы — начисления отменяются
  3. Переплата — автоматически пересчитывается через FIFO
  4. Статус жильца → "Выселен"
  5. Место в комнате освобождается
  6. Записывается история и аудит

================================================================================
6. ПЕРЕВОД В ДРУГУЮ КОМНАТУ
================================================================================

При переводе:

  1. Старое назначение закрывается
  2. Создаётся новое назначение в новой комнате
  3. Начисления пересчитываются:
     - Текущий месяц: пропорционально дням в каждой комнате
     - Будущие месяцы: по цене новой комнаты
  4. Платежи перераспределяются через FIFO
  5. Записывается история (StayRecord) с причиной "Перевод"

================================================================================
7. ФИНАНСЫ
================================================================================

--------------------------------------------------------------------------------
7.1. Начисления (Charges)
--------------------------------------------------------------------------------

Создаются автоматически при заселении на каждый месяц договора.

Расчёт суммы:
  - Полный месяц: цена комнаты (за место)
  - Неполный месяц: пропорционально дням
    Формула: (цена / дней_в_месяце) x фактических_дней

Статусы начислений:
  - Ожидает оплаты
  - Частично оплачен
  - Оплачен
  - Просрочен
  - Отменён

Срок оплаты: 25-е число каждого месяца.

--------------------------------------------------------------------------------
7.2. Платежи (Payments)
--------------------------------------------------------------------------------

Способы оплаты: наличные, банковский перевод.
(Онлайн-оплата через Payme/Click — запланирована)

При создании платежа:
  1. Указывается жилец и сумма
  2. Система автоматически распределяет по FIFO
  3. Сначала закрываются самые старые неоплаченные начисления
  4. Частичная оплата тоже поддерживается

Пример FIFO:
  Начисления:
    Январь — 500 000 (не оплачен)
    Февраль — 500 000 (не оплачен)
    Март — 500 000 (не оплачен)

  Платёж: 800 000
  Результат:
    Январь — 500 000 (оплачен полностью)
    Февраль — 300 000 (частично оплачен, остаток 200 000)
    Март — 500 000 (не оплачен)

--------------------------------------------------------------------------------
7.3. Баланс жильца
--------------------------------------------------------------------------------

В карточке жильца отображается:
  - Всего начислено
  - Всего оплачено
  - Задолженность

================================================================================
8. ОТЧЁТЫ
================================================================================

Доступные отчёты:

  1. Сводка — общие цифры: жильцы, свободные места, долг, оплаты за месяц
  2. Заполняемость — по корпусам и этажам (вместимость, занято, свободно, %)
  3. Свободные комнаты — список доступных комнат с фильтром по полу
  4. Должники — жильцы с задолженностью (отсортированы по сумме долга)
  5. Платежи — за период, с фильтром по способу оплаты
  6. Жильцы — полный список с фильтрами по статусу, факультету, полу

================================================================================
9. КОНТРОЛЬ ДОСТУПА (Hikvision)
================================================================================

Журнал входов и выходов жильцов через турникеты/двери.

Каждое событие содержит:
  - Жилец
  - Направление (вход / выход)
  - Время
  - Устройство (название турникета)
  - Номер карты

Фильтрация: по жильцу, направлению, устройству, дате.

Интеграция с Hikvision настраивается отдельно
(через Hik-Connect API или локальный агент в сети университета).

================================================================================
10. АУДИТ
================================================================================

Все критические действия записываются:
  - Кто сделал (пользователь)
  - Что сделал (создание / изменение / удаление)
  - Какой объект (жилец, договор, платёж и т.д.)
  - Что именно изменилось (старое значение → новое)
  - Когда (дата и время)
  - Откуда (IP-адрес)

Фильтрация: по действию, разделу, пользователю, дате.

================================================================================
11. TELEGRAM-БОТ
================================================================================

Функции бота:
  - Привязка аккаунта через отправку контакта (/start)
  - Получение OTP-кодов для входа в систему
  - Привязка телефона к Telegram для будущей авторизации
